# 데이터 일관성과 책임 경계

PostgreSQL이 계정, 권한, 설정, 링크, 클릭 제한, 클릭 통계의 기준 저장소다. Redis와 ClickHouse의 성공 여부로 이 데이터의 커밋 여부를 결정하지 않는다.

## 변경 단위

- 계정 생성과 인증 수단 연결, 자동 권한 배정은 같은 Sequelize 트랜잭션에 참여한다. 최초 관리자 생성과 마지막 활성 관리자 보호는 공통 트랜잭션 잠금으로 직렬화한다.
- 인증 토큰 소비와 계정 변경을 함께 커밋한다. 세션 버전과 패스키 카운터는 DB에서 원자적으로 변경한다. 서명된 인증 challenge와 사용한 TOTP 시간 구간은 기존 요청 제한 테이블에 기록해 재사용을 막는다.
- 비밀번호 변경·삭제와 관리자 비밀번호 재설정은 같은 트랜잭션에서 세션 버전을 올린다. 본인이 변경한 경우 현재 브라우저에는 새 세션을 발급하고 이전 세션은 무효화한다.
- 권한 그룹 설정과 그 설정으로 인한 자동 배정을 함께 커밋한다. 자동 배정은 수동 배정의 사유·만료일을 덮어쓰지 않는다.
- 사이트 설정과 플러그인 설정 행을 함께 저장한다. `updateSettings`는 잠긴 최신 설정을 변경하는 콜백을 받는다. 오래된 전체 설정 객체로 다른 섹션을 덮어쓰지 않는다.
- 초대 생성·수락·회전·취소와 링크 수정·삭제는 같은 링크 행을 먼저 잠근다. 클릭 제한 확인, 사용 횟수 증가, 추적 큐 삽입도 같은 트랜잭션이다.
- 속도 제한과 계정 복구 요청 카운터는 PostgreSQL에 저장한다. 프로세스 수와 재시작에 따라 제한이 초기화되지 않는다.

일반적인 행 변경은 Sequelize의 관리 트랜잭션과 `LOCK.UPDATE`를 사용한다. 여러 행 또는 아직 존재하지 않는 행에 걸친 불변조건에만 PostgreSQL 트랜잭션 advisory lock을 Sequelize로 실행한다. 스키마 초기화 잠금은 별도 Sequelize 연결에서 유지하므로 작은 애플리케이션 풀이나 `CREATE INDEX CONCURRENTLY`와 충돌하지 않는다.

## 읽기와 부수 효과

설정은 한 SQL 문으로 읽는다. 권한은 매칭되는 그룹만 단일 SQL 스냅샷으로 읽고, 통계의 여러 쿼리는 일관된 DB 스냅샷에서 읽는다. 인증·권한·설정·리다이렉트의 오래된 프로세스 캐시로 취소된 권한을 다시 허용하지 않는다. 이 선택은 DB에서 최신 값을 읽는 비용이 있다. 요청 내 설정 재사용과 권한 단일 조회, 클릭 큐 배치 처리로 왕복 횟수를 줄인다. 측정 결과는 [성능 검증](performance.md)을 참고한다.

SMTP/HTTP 메일과 ClickHouse 복제는 PostgreSQL과 분산 트랜잭션을 구성하지 않는다. 외부 호출은 DB 잠금 밖에서 실행한다. 메일 실패 보상은 해당 요청이 발급한 토큰이 아직 현재 값일 때만 적용한다. ClickHouse는 전송 예약과 완료 표시를 PostgreSQL 이벤트 행에 보관하는 보조 복제본이다. 전송 실패·worker 중단은 원본이 남아 있는 동안 재시도하며, HTTP 대기 중 DB 잠금을 잡지 않는다. 재전송은 `ReplacingMergeTree`와 `FINAL` 조회로 중복 집계를 막는다. PostgreSQL의 삭제는 독립 미러에 자동 전파하지 않으며 사용자 통계는 PostgreSQL을 읽는다. SMTP 수신 여부까지 정확히 한 번 보장하지는 않는다.

ACID의 내구성은 PostgreSQL의 WAL·동기 커밋·스토리지 설정에도 의존한다. 이 코드는 운영 DB 설정을 변경하지 않는다. 스키마 변경은 기존 데이터에서 마이그레이션 검증 후 배포한다. 이전 Redis 클릭 큐의 전환 주의사항은 README의 클릭 저장소 설명을 따른다.

## 코드 책임

라우트는 인증·권한 확인, 요청/응답 처리를 담당한다. 관리자 설정의 폼 변환·검증은 `src/lib/server/admin-settings.ts`, 정규화·저장은 `settings.ts`가 담당한다. 계정·권한·링크 불변조건은 각 공유 변경 함수에서 검사하므로 API와 웹 호출자가 같은 규칙을 사용한다.

플러그인은 기존 레지스트리와 계약을 통해 확장한다. SQL 한 번을 전달하는 저장소 클래스나 서비스 래퍼를 추가하지 않는다. 관련된 쓰기에만 명시적으로 `Transaction`을 전달한다. 플러그인의 외부 부수 효과를 자동으로 롤백할 수 있다고 가정하지 않는다.

## 회귀 검증

링크 소유권은 계정 ID 또는 익명 브라우저 식별자로만 판단한다. 같은 IP의 다른 브라우저를 소유자로 인정하지 않는다. 목록·수정·통계·삭제·공유는 `link-ownership.ts`의 규칙을 사용한다. 쿠키를 잃은 익명 사용자는 IP만으로 이전 링크를 다시 관리할 수 없다.

링크 상태 확인은 `public-http.ts`에서 공개 HTTP(S) 주소만 요청한다. 각 이동 단계에서 DNS 응답 전체를 검사하고 검증한 IP로 연결하므로 내부망·메타데이터 주소와 DNS rebinding을 차단한다. 설정된 프록시는 CONNECT 또는 등록된 `connect` 전송을 통해 적용한다. 응답은 512 KiB, 요청 한 번의 DNS·이동·수신은 8초로 제한한다. 프록시 플러그인이 `connect`를 제공하지 않으면 상태 확인은 실패하며 직접 연결로 우회하지 않는다.

주소·소유권과 실제 로컬 프록시 전송을 별도로 검증할 수 있다. 개발 서버나 외부 사이트에 요청하지 않는다.

```bash
yarn node scripts/check-public-security.mjs
yarn node scripts/check-public-http.mjs
```

Node.js 24+, 설치된 Yarn 의존성, 비어 있는 전용 PostgreSQL 테스트 DB가 필요하다. 테스트 DB 이름에는 `test`가 포함되어야 한다. 실제 `.env`는 읽지 않는다.

```bash
TEST_DATABASE_URL=postgres://postgres:password@127.0.0.1:5432/shortlink_test yarn node scripts/check-invariants.mjs
```

이 명령은 개발 서버를 시작하지 않는다. Vite로 테스트 진입점만 임시 번들링하고 실제 도메인 함수에 동시 요청·실패 주입을 실행한다. 테스트 DB에는 테스트 데이터가 남으므로 운영 DB를 지정하지 않는다.

검증 범위는 최초/마지막 관리자 경쟁, 인증 토큰 단일 소비, 세션·패스키 갱신, 자동 권한 배정 롤백, 동시 설정 저장, 요청 제한, 초대 변경, 클릭 제한 및 큐 롤백이다. 이 검증은 모든 운영 장애나 외부 플러그인의 정확성을 증명하지 않는다.

관련 규칙: [Sequelize 트랜잭션](https://sequelize.org/docs/v6/other-topics/transactions/), [PostgreSQL 잠금](https://www.postgresql.org/docs/current/explicit-locking.html).
